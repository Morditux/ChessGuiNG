# ------------------------------------------------------------------------------
# PHASE 1 : CORRECTIONS RAPIDES & OPTIMISATIONS CRITIQUES (Priorité Haute)
# Objectif : Résoudre les bugs d'ordonnancement, éliminer le goulot SEE et fiabiliser la TT.
# ------------------------------------------------------------------------------
[x] 1.1 Réécriture optimisée de SEE (Static Exchange Evaluation)
    - Fichier : heuristicsearch.cpp (`seeValue`, `leastValuableAttacker`)
    - Problème : `leastValuableAttacker` balaye les 64 cases à chaque étape de la boucle SEE.
    - Action : Rayonner directement depuis la case cible `to` (pions, cavaliers, rayons diagonaux et orthogonaux).
    - Bénéfice : Gain de vitesse estimé de 5x à 10x sur les calculs d'échanges tactiques.

[x] 1.2 Correction et fiabilisation de l'ordonnancement des coups (Move Ordering)
    - Fichier : heuristicsearch.cpp (`computeMoveOrdering`)
    - Action 1.2.1 : Corriger la prise en compte de la promotion lors d'une capture (ex. exd8=Q).
      Actuellement, `move.promotion` est ignoré si `target.has_value()`.
    - Action 1.2.2 : Utiliser SEE pour séparer les bonnes/égales captures (SEE >= 0) des mauvais sacrifices (SEE < 0).
      Reléguer les captures perdantes après les coups tueurs (Killer Moves) et coups d'historique.
    - Bénéfice : Coupures bêta beaucoup plus précoces, réduction drastique du nombre de nœuds explorés.

[x] 1.3 Préservation du meilleur coup dans la Transposition Table (TT) sur Fail-Low
    - Fichier : heuristicsearch.cpp (`storeTable`)
    - Problème : Lors d'un échec vers le bas (`best <= alphaOriginal`), `flag = TtUpper` et `bestMove` est vide (`{}`).
      La TT écrase le coup optimal trouvé par une itération précédente.
    - Action : Conserver le `bestMove` déjà présent dans l'entrée TT si le nouveau coup proposé est nul.
    - Bénéfice : Évite l'amnésie des coups optimaux lors des réitérations et fenêtres d'aspiration.

[x] 1.4 Tests de validation et non-régression Phase 1
    - Exécuter et étendre `tests/heuristiceval_test.cpp` pour valider les corrections.


# ------------------------------------------------------------------------------
# PHASE 2 : ÉLAGAGES AVANCÉS & ROBUSTESSE DE LA RECHERCHE (Priorité Moyenne-Haute)
# Objectif : Accroître la profondeur de recherche effective à temps de calcul égal.
# ------------------------------------------------------------------------------
[ ] 2.1 Implémentation du Reverse Futility Pruning (RFP / Static Null Move Pruning)
    - Fichier : heuristicsearch.cpp (`negamax`)
    - Action : À profondeur 1 et 2, si `staticEval - margin * depth >= beta` hors échec, couper immédiatement.
    - Bénéfice : Économie massive de nœuds dans les positions dominantes sans faire de coup nul complet.

[ ] 2.2 Heuristique de riposte (Countermove Heuristic)
    - Fichier : heuristicsearch.cpp (`SearchState`, `computeMoveOrdering`)
    - Action : Mémoriser le coup réfutant le coup adverse précédent dans un tableau `countermoves[piece][to]`.
    - Bénéfice : Meilleur tri des coups calmes en complément des deux Killer Moves.

[ ] 2.3 Compteur de génération et vieillissement de la Transposition Table (Aging)
    - Fichier : heuristicsearch.cpp (`TranspositionTable`, `TtEntry`)
    - Action : Ajouter un identifiant de génération incrémenté à chaque nouvelle recherche racine.
      Politique de remplacement combinant profondeur et fraîcheur temporelle.
    - Bénéfice : Élimination des branches obsolètes lors de longues sessions d'analyse ou de jeu continu.

[ ] 2.4 Optimisation du test de matériel non-pion pour le coup nul (Null Move)
    - Fichier : heuristicsearch.cpp (`hasNonPawnMaterial`)
    - Action : Remplacer le balayage des 64 cases par un décompte incrémental ou un masque de pièces majeures/mineures.


# ------------------------------------------------------------------------------
# PHASE 3 : OPTIMISATIONS DE PERFORMANCE & PARALLÉLISME (Priorité Moyenne)
# Objectif : Maximiser le débit de calcul (NPS) et l'efficacité multi-cœurs.
# ------------------------------------------------------------------------------
[ ] 3.1 Implémentation d'un Cache de Structure de Pions (Pawn Cache)
    - Fichiers : heuristiceval.cpp, heuristicsearch.cpp
    - Contexte : La structure de pions ne change pas pour ~85% des coups joués.
    - Action : Stocker les résultats de `evaluatePawnStructure` et `evaluateSpace` dans une table de hachage
      dédiée (ex. 8192 entrées, ~100 Ko) indexée par le Zobrist hash des pions seuls.
    - Bénéfice : Réduction de 50% à 70% du coût de l'évaluation statique sur les nœuds sans mouvement de pion.

[ ] 3.2 Amélioration du parallélisme à la racine (Young Brothers Wait / Lazy SMP)
    - Fichier : heuristicsearch.cpp (`parallelRootSearch`, `SearchPool`)
    - Problème : Actuellement, tous les workers cherchent les coups racines en parallèle avec une fenêtre initiale large.
    - Action : Appliquer le principe YBW : chercher d'abord le coup 0 seul avec le premier thread ;
      une fois `alpha` mis à jour, distribuer les coups restants aux autres threads avec fenêtre étroite.
    - Bénéfice : Fin du gaspillage de calculs parallèles sur des sous-arbres voués à être coupés.

[ ] 3.3 Participation active du thread appelant dans SearchPool
    - Fichier : heuristicsearch.cpp (`SearchPool::run`)
    - Action : Faire exécuter une part des travaux par le thread appelant au lieu de le mettre en attente passive.
